## กติกาทุก task (จาก AGENTS.md)
- ทำทีละ task ห้ามรวมขอบเขต
- task Test ต้องแดงก่อน แล้ว task Implement ที่ตามมาทำให้เขียว
- task Test ที่ไม่มี Implement คู่ คือเทสของพฤติกรรมเดิม → ถ้าแดงเพราะโค้ดไม่ตรง SPEC ให้หยุดแล้วแตก task ใหม่ ห้ามแก้เทสให้ผ่าน
- task ที่ขึ้นต้นด้วย ⚖ ต้องให้ human ตัดสินก่อน แล้วแก้ AC ใน SPEC ให้ตรงกับที่ตัดสิน จึงเริ่มเขียนเทส
- กฎธุรกิจใหม่ต้องมีกฎที่ฐานข้อมูลรองรับ ไม่ใช่แค่ในโปรแกรม
- เปลี่ยนช่องทางหรือคำตอบของระบบ → แก้ docs/openapi.yaml และ backend/README.md ก่อน แล้วถาม human
- เทสใช้ internal/testsupport (หนึ่งเทสหนึ่งฐานข้อมูลและโฟลเดอร์ไฟล์แยก ลบทิ้งเองเมื่อจบ) · ไฟล์หรือข้อมูลอื่นที่สร้างเพื่อเทสต้องลบทิ้งหลังเทส
- ทุก Implement ที่ปิดช่องว่างได้ ต้องตัดป้ายที่เกี่ยวข้องใน SPEC ออกด้วย

## คำสั่งใน DoD
- CHECK = cd backend && gofmt -l . && go build ./... && go vet ./... (gofmt ต้องไม่มี output)
- TEST(แพ็กเกจ, ชื่อเทส) = cd backend && go test ./internal/แพ็กเกจ/... -run 'ชื่อเทส' -race -count=1
- ALL = cd backend && go test ./... -race -count=1
