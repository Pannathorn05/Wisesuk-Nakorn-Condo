## Section map จาก prototype (ภาพ 51)

**Header**: โลโก้ "วิเศษสุขนครคอนโด / และหอพักในเครือ" อย่างเดียว ชิดซ้าย มีเส้นคั่นใต้ header
— **ไม่มีเมนูนำทาง (หน้าหลัก/สาขาของเรา/ค้นหาห้องพัก/ติดต่อเรา) และไม่มีปุ่มเข้าสู่ระบบ/สมัครสมาชิก**
ต่างจาก `Header` ของฝั่ง Guest ที่ implement ไปแล้ว — เป็นคนละ layout กัน

**การ์ดฟอร์ม** (ลอยกลางพื้นหลังครีม เหมือนหน้า Login ฝั่ง Guest):
1. หัวการ์ด "เข้าสู่ระบบ" + subtext "เข้าสู่ระบบเพื่อจองห้องพักออนไลน์" (ดู Gap — ข้อความนี้น่าจะหลุดมาจากหน้า Guest)
2. ช่อง "อีเมล" — ไอคอนซองจดหมาย, placeholder `your@gmail.com`
3. ช่อง "รหัสผ่าน" — ไอคอนแม่กุญแจ + ไอคอนตา toggle แสดง/ซ่อน
4. checkbox "จดจำฉัน" (ซ้าย) + ลิงก์ "ลืมรหัสผ่าน?" (ขวา) แถวเดียวกัน
5. ปุ่ม "เข้าสู่ระบบ" เต็มความกว้าง สีน้ำตาลเข้ม
6. **ไม่มีลิงก์ "ยังไม่มีบัญชี? สมัครสมาชิก" ท้ายการ์ด** (ต่างจากหน้า Guest — ผู้ดูแลไม่สมัครเอง หัวหน้าผู้ดูแลเป็นคนสร้างบัญชีให้ผ่าน `POST /api/v1/superadmin/staff`)

ตรวจแล้ว: การ์ดฟอร์มหน้าตาเหมือนหน้า Login ฝั่ง Guest (ภาพ 19) ทุกจุด **ยกเว้นข้อ 6** และ header ข้างต้น
→ reuse `AuthCard` / `AuthInput` / `AuthForm.css` ที่ทำไว้แล้วใน FE-21 ได้ทั้งหมด ไม่ต้องสร้าง component ใหม่

## API จริงที่มีอยู่แล้ว (`docs/openapi.yaml`) — เชื่อมตรงนี้ ห้ามเดา endpoint อื่น

- **`POST /api/v1/auth/login` ใช้ร่วมกันทุกบทบาท** (summary ใน spec เขียนไว้ตรง ๆ ว่า "ใช้ endpoint เดียวทุกบทบาท") body `LoginRequest {email, password}` → สำเร็จ `200` คืน `AuthResult {access_token, refresh_token, user}` เหมือนหน้า Guest เป๊ะ
  **แปลว่าไม่มี endpoint login แยกสำหรับ admin — ห้ามสร้าง/เดา endpoint ใหม่** ตัว `authApi.login()` ที่ทำไว้แล้วใน FE-21 ใช้ต่อได้เลย
- `AuthResult.user.role` เป็น enum `UserRole` = `member` | `admin` | `superadmin` และ spec เขียนกำกับไว้เองว่า
  *"frontend ใช้ค่านี้ตัดสินใจว่าจะพาผู้ใช้ไปหน้าไหนหลังล็อกอิน (member → หน้าสมาชิก, admin → หน้าผู้ดูแล, superadmin → หน้าหัวหน้าผู้ดูแล)"*
  → **การ redirect ตาม role เป็นหน้าที่ของ frontend ตามสัญญา API ที่มีอยู่แล้ว ไม่ใช่การเดาเอง**
- error เหมือนหน้า Guest: `401 invalid_credentials` ("อีเมลหรือรหัสผ่านไม่ถูกต้อง" — ข้อความเดียวกันทั้งอีเมลผิด/รหัสผ่านผิด ห้ามพยายามแยก) · `403 account_disabled` ("บัญชีนี้ถูกปิดใช้งาน")
- ปลายทางหลัง login มีอยู่จริงแล้วฝั่ง backend: `GET /api/v1/admin/dashboard`, `/api/v1/admin/activity-logs` (admin) และกลุ่ม `/api/v1/superadmin/*` เช่น `/superadmin/branches`, `/superadmin/staff` (หัวหน้าผู้ดูแล) — แต่ **หน้าเว็บของปลายทางพวกนี้ยังไม่มี** (ดู Gap)
- ที่เก็บ token เดิม `src/utils/authStorage.jsx` + `useAuthState` (FE-21/FE-24) ใช้ต่อ **ห้ามสร้างระบบ auth ที่สองซ้อน** (docs/c.md ข้อ 20)

## Gap ที่เจอ — ต้องตัดสินใจก่อน implement ไม่ใช่เดาเอง

- **subtext ในภาพเขียนว่า "เข้าสู่ระบบเพื่อจองห้องพักออนไลน์"** ซึ่งเป็นข้อความของฝั่ง Guest (ผู้ดูแลไม่ได้เข้ามาจองห้อง) เกือบแน่ว่าเป็น copy-paste ค้างมาจากภาพ 19 ตอนทำ prototype — ต้องเลือก: (ก) ทำตาม prototype ตรงตัว หรือ (ข) เปลี่ยนเป็นข้อความที่ตรงบริบท เช่น "สำหรับผู้ดูแลระบบและหัวหน้าผู้ดูแลระบบ" **แนะนำ (ข) แต่ต้องให้ทีมยืนยันก่อน** เพราะขัด hard rule ข้อ 3 (prototype เป็น source of truth ด้านข้อความ)
- **prototype ไม่ได้บอก URL ของหน้านี้** ต้องเลือกเอง: `/admin/login` (แยกชัด เป็นคนละ layout คนละกลุ่มผู้ใช้ — **แนะนำอันนี้**) หรือใช้ `/login` ร่วมกับ Guest แล้วสลับ layout ตามอะไรสักอย่าง (ซับซ้อนกว่าและทำให้ header ของ Guest เพี้ยน) ต้องเคาะก่อนทำ FE-26
- **เคส role ไม่ตรงประตูที่เข้ามา** — เพราะ backend ใช้ endpoint เดียวทุกบทบาท ถ้า `member` กรอกอีเมล/รหัสผ่านถูกที่หน้า `/admin/login` backend จะตอบ `200` สำเร็จปกติ (ไม่ได้มองว่าผิด) **frontend ต้องเป็นคนตัดสินใจเอง** ว่าจะ:
  (ก) ปฏิเสธ: เคลียร์ token ที่เพิ่งได้มาทิ้ง แล้วโชว์ error "บัญชีนี้ไม่มีสิทธิ์เข้าใช้ระบบผู้ดูแล" (**แนะนำ** — ตรงกับความคาดหวังของประตูเฉพาะทาง และไม่ทำให้ member หลงอยู่ในโซน admin)
  (ข) ยอมให้ผ่านแล้ว redirect ไปโซน Guest/Member ตาม role
  ทั้งสองทางไม่มีใน prototype ต้องให้ทีมเคาะ
- **[อัปเดต 2026-09-22] "ลืมรหัสผ่าน" มี endpoint แล้ว** — `POST /api/v1/auth/forgot-password` และ
  `POST /api/v1/auth/reset-password` ถูกเพิ่มเข้า `docs/openapi.yaml` แล้ว (ตรงกับหมายเหตุใน README ว่า
  gap เดิมของฝั่ง Guest ตกไปแล้ว) แต่ **หน้าเว็บ `/forgot-password` / `/reset-password` ยังไม่มีใครทำ**
  (ยังไม่แตก task) ตอน implement FE-27 จึงยังใช้ข้อความบอกให้ติดต่อหัวหน้าผู้ดูแลไปก่อน ไม่ทำเป็นลิงก์
  ที่กดแล้วไป 404 — **เมื่อไหร่ที่ทำหน้า forgot-password เสร็จ ต้องกลับมาเปลี่ยนทั้งหน้านี้และหน้า Login
  ของ Guest (ที่ยังลิงก์ไป `/contact` อยู่) พร้อมกัน**
- ~~**"ลืมรหัสผ่าน?" ยังไม่มี endpoint รองรับ**~~ (ข้อมูลเดิม ณ ตอนแตก task — ดูข้อด้านบน) (เช็คทั้ง `docs/openapi.yaml` แล้วไม่มี `forgot`/`reset-password` ใด ๆ) เหมือน gap เดิมของหน้า Guest — แต่ทางแก้ของ Guest (ลิงก์ไป `/contact`) **ใช้กับ admin ไม่ได้** เพราะหน้าติดต่อเป็นของลูกค้า ทางเลือกที่ไม่ผิดกฎ: แสดงเป็นข้อความบอกให้ติดต่อหัวหน้าผู้ดูแลระบบ (superadmin เป็นคนจัดการบัญชี staff ผ่าน `/superadmin/staff` อยู่แล้ว) หรือซ่อนลิงก์นี้ไปเลยในหน้า admin — ต้องเคาะ
- **หน้าปลายทางหลัง login ยังไม่มีสักหน้า** — `/admin/dashboard` และหน้าของ superadmin (ภาพ 52) ยังไม่ถูกแตก task/สร้าง ดังนั้น task ชุดนี้ **จบได้แค่ "login สำเร็จแล้วพาไปหน้าปลายทางที่ถูกต้องตาม role"** ซึ่งช่วงแรกจะเป็น placeholder เท่านั้น ถ้าอยากได้ flow ที่ใช้งานได้จริงต้องแตก task หน้าแดชบอร์ด (ภาพ 52 เป็นต้นไป) ต่อ
- **checkbox "จดจำฉัน"** ไม่มี field รองรับใน `LoginRequest` เหมือนกับฝั่ง Guest — ตัดสินใจไว้แล้วในรอบ FE-22 ว่าเป็น UI เฉย ๆ ไม่ผูก logic ให้ทำเหมือนกันเพื่อความสม่ำเสมอ (ถ้าจะเปลี่ยนต้องเปลี่ยนพร้อมกันทั้งสองหน้า)

**FE-26 · Layout + route ของโซนผู้ดูแล**
- ทำ: สร้าง layout สำหรับหน้า auth ของผู้ดูแล — header โลโก้อย่างเดียว (ไม่มีเมนู/ปุ่ม auth) + เส้นคั่นใต้ header ตามภาพ 51 · เพิ่ม route `/admin/login` ใน `src/routes/AppRoutes.jsx` · **ห้ามแก้ `Header` ของ Guest ให้รองรับหลายโหมด** ให้แยกเป็น component ใหม่ (เช่น `components/layout/AuthHeader`) เพราะ Guest header มีเมนู/ปุ่ม auth/เมนูมือถือที่ไม่เกี่ยวกันเลย
- ขึ้นกับ: —
- DoD: เข้า `/admin/login` แล้วเห็น header โลโก้อย่างเดียวจริง (ไม่มีเมนู) · หน้า Guest ทุกหน้ายังใช้ `Header` เดิมไม่เปลี่ยน (เช็คด้วยตาที่ `/`, `/branches`, `/login`) · ไม่มี route เดิมพัง

**FE-27 · หน้า Login ผู้ดูแล/หัวหน้าผู้ดูแล — เชื่อม `POST /auth/login` จริง**
- ทำ: ฟอร์มตาม section map โดย **reuse `AuthCard` + `AuthInput` + `AuthForm.css` จาก FE-21 ทั้งหมด** (ต่างจากหน้า Guest แค่ไม่มีลิงก์สมัครสมาชิกท้ายการ์ด และข้อความ subtext ตามที่เคาะใน Gap) → validate ฝั่ง client (อีเมล format, ทั้งคู่ห้ามว่าง) ด้วย `validateLogin` เดิม → เรียก `authApi.login()` เดิม → ระหว่างยิง disable ปุ่ม + โชว์ loading → error โชว์ข้อความจาก `ApiError.message` จริงเหนือปุ่ม (401/403 ใช้ข้อความ backend ตรง ๆ ห้ามเขียนเอง)
- ขึ้นกับ: FE-26
- DoD: E2E ครบ idle/submitting/error(401 invalid_credentials, 403 account_disabled, NetworkError)/success · toggle แสดง/ซ่อนรหัสผ่านตรงกับภาพ 51 ทั้ง 2 state · ไม่มีลิงก์ "สมัครสมาชิก" ในหน้านี้ · ยืนยันว่าไม่ได้สร้าง `authApi`/ที่เก็บ token ชุดใหม่ (ใช้ของเดิมล้วน)

**FE-28 · Redirect ตาม role + กันบัญชีผิดสิทธิ์ (route guard)**
- ทำ: หลัง login สำเร็จ อ่าน `user.role` จาก `AuthResult` แล้วพาไปปลายทางตามสัญญาใน spec (`admin` → หน้าผู้ดูแล, `superadmin` → หน้าหัวหน้าผู้ดูแล) · เคส `member` ทำตามที่เคาะใน Gap (แนะนำ: เคลียร์ token + โชว์ error ว่าไม่มีสิทธิ์) · สร้าง guard สำหรับ route โซนผู้ดูแล (เช่น `RequireRole`) ที่เด้งกลับ `/admin/login` เมื่อยังไม่ login หรือ role ไม่ถึง · เก็บ `user.role` ไว้ให้ component อื่นอ่านได้ (ต่อยอดจาก `authStorage`/`useAuthState` เดิม **ห้ามสร้าง store ใหม่**)
- ขึ้นกับ: FE-27
- DoD: login ด้วยบัญชี `admin` จริงจาก backend แล้วไปปลายทางของ admin · บัญชี `superadmin` ไปปลายทางของ superadmin · บัญชี `member` ไม่หลุดเข้าโซนผู้ดูแล (พฤติกรรมตามที่เคาะ) · เข้า URL ของโซนผู้ดูแลตรง ๆ ทั้งที่ยังไม่ login ต้องเด้งไป `/admin/login` · reload หน้าแล้วสถานะ login/role ยังถูกต้อง (อ่านจาก storage ไม่ใช่ state ที่หายตอน reload)
