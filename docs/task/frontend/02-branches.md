## Gap ที่เจอ — เช็คกับ backend ที่รันจริงแล้ว (curl `localhost:8080`) ไม่ใช่แค่เดาจาก prototype

- **`nearby_places` หายไปจริงสำหรับ 2 ใน 3 สาขา** — ไม่ใช่แค่ array ว่าง แต่ **key หายไปทั้ง key** จาก response (`omitempty` ฝั่ง backend) ทั้งบน `GET /branches` และ `GET /branches/:id` มีแค่ "วิเศษสุขนครคอนโด ประชาอุทิศ 45" ที่มีข้อมูล (4 รายการ) ส่วน "บางแค" กับ "เจริญกรุงเพลส" ไม่มีเลย → ต้องเขียนโค้ดกัน `undefined` ไว้ (`branch.nearby_places ?? []`) และต้อง "success" QA case กับสาขาที่ไม่มีข้อมูลจริง ๆ ไม่ใช่เทสแต่กรณีมีข้อมูล
- **`daily_price_from` หายไปจริงสำหรับสาขาที่ไม่มีห้องรายวัน** (บางแค) เหมือนกัน (key หาย ไม่ใช่ 0) → บรรทัด "รายวัน:" ต้องโชว์ `-` เมื่อ key ไม่มี ตรงกับที่ prototype ภาพ 7 โชว์ "รายวัน: -"
- **ไม่มี field ราคา/ค่าบริการที่จอดรถ** ใน Branch เลย (ตรวจ key ทั้งหมดของ response แล้วไม่มี) แต่ prototype ภาพ 5 (ประชาอุทิศ 45) โชว์ "ที่จอดรถ: ฟรี" และภาพ 8 (บางแค) โชว์ "ที่จอดรถ: 500 บาท/เดือน" — เป็นตัวเลข ไม่ใช่ boolean เดียว → **ไม่มี field จริงรองรับตอนนี้** ตัดสินใจตอนทำ FE-10: ใช้ amenity `parking` (มี/ไม่มี) แสดงแค่ "มีที่จอดรถ" / "ไม่มีที่จอดรถ" (ไม่เดาราคา) หรือข้ามบรรทัดนี้ไปก่อน — **ห้ามพิมพ์ตัวเลขราคาที่ไม่มีข้อมูลจริงรองรับ**
- **"รปภ. 24 ชั่วโมง" ไม่มีใน amenities catalog จริง** (ตรวจ `GET /api/v1/amenities` ครบ 12 code แล้วไม่มี) แต่ prototype ใส่ "รปภ." ต่อท้ายกล่อง "สิ่งอำนวยความสะดวก" ของทุกสาขาเหมือนเป็นข้อความตายตัว — เหมือนกับ gap เดียวกับ facilities strip หน้า Home (ดู `01-homepage.md`) → **ห้ามยัด "รปภ." เข้าไปเองถ้า `branch.amenities` จริงไม่มี** ให้ render เท่าที่ API มีจริงเท่านั้น
- **`map_url` ว่างเปล่าทุกสาขา** ในข้อมูลจริงตอนนี้ (ยังไม่ได้ตั้งค่า) → ต้องมี empty-state "ยังไม่มีแผนที่สำหรับสาขานี้" รูปแบบจริงของ `map_url` (embed URL ตรง ๆ หรือลิงก์ธรรมดา) ยังไม่รู้เพราะไม่มีข้อมูลตัวอย่าง — ให้เขียนโค้ดรองรับทั้ง 2 กรณีอย่างปลอดภัย (ลอง iframe embed ก่อน ถ้าไม่ใช่รูปแบบ embed ให้ fallback เป็นลิงก์ "เปิดใน Google Maps" แทน) และห้ามฝัง API key แผนที่ใหม่เอง (`docs/c.md` ข้อ 22)
- **`deposit`/`advance_payment` เป็น 0 ทุกสาขาในข้อมูลจริง** แต่ prototype โชว์ "เงินประกัน: จ่ายล่วงหน้า 3 เดือนของราคาห้องพัก" เป็นข้อความสูตรคำนวณ ไม่ใช่ตัวเลข — ใช้ field `deposit`/`advance_payment` โชว์เป็นบาทจริงถ้า > 0 ในอนาคต ตอนนี้ (เป็น 0 ทั้งหมด) ให้โชว์ข้อความ static ตามสูตรที่ prototype เขียนไปก่อนได้ (เป็น business rule ทั่วไปของระบบ ไม่ใช่ข้อมูลเฉพาะสาขา)
- **chip ไฮไลต์บนหน้ารวมสาขา** ("2 อาคาร 5 ชั้น", "ใกล้ร้านสะดวกซื้อ", "ห้องกว้าง 21 ตร.ม.", "ลิฟท์ 2 ตัว") ไม่ได้มาจาก field เดียวแบบตรงไปตรงมา — ส่วนที่ตรงกับ field จริงแน่ ๆ คือ "{building_count} อาคาร {floor_count} ชั้น" เท่านั้น ส่วนอื่น ๆ (ห้องกว้างกี่ ตร.ม., ลิฟท์กี่ตัว) ไม่มี field รองรับ (ขนาดห้องอยู่ระดับ Room ไม่ใช่ Branch, จำนวนลิฟท์ไม่มีเก็บเลย) → ใช้แค่ (ก) chip อาคาร/ชั้น จาก field จริง และ (ข) เลือก amenity เด่นสูงสุด 2 ตัวจาก `branch.amenities` จริงมาทำเป็น chip (เช่นมี `convenience-store` → "ใกล้ร้านสะดวกซื้อ", มี `furniture` → "มีเฟอร์นิเจอร์ครบครัน") **ห้ามคำนวณ/เดาตัวเลขขนาดห้องหรือจำนวนลิฟท์ที่ไม่มีข้อมูลจริงรองรับ**
- **`tagline` คือ source ของบรรทัดท้ายบนหน้ารวมสาขา** ("ห่างจาก...") — เช็คแล้วตรงกับ prototype แนวคิดเดียวกัน (ระยะทาง/จุดเด่น) แต่ค่าจริงในข้อมูล seed ไม่ตรงคำต่อคำกับ prototype (คนละคนเขียน) → render `branch.tagline` ตรง ๆ ตามที่ backend ส่งมา ไม่ต้องพยายามคำนวณจาก `nearby_places` เอง

**FE-09 · หน้ารวมสาขา (Branches List)** — แทนที่ `BranchesPage` placeholder

**FE-10 · หน้ารายละเอียดสาขา — โครง + รายละเอียด + สิ่งอำนวยความสะดวก** — แทนที่ `BranchDetailPage` placeholder
- ทำ: เชื่อม `GET /api/v1/branches/:branchID` — header (title+address), tab switcher "รูปภาพ"/"แผนที่" (default รูปภาพ, ยังไม่ต้องทำเนื้อหา tab แผนที่ในรอบนี้ ไปทำใน FE-12), gallery carousel (placeholder รูปแบบเดียวกับ hero เพราะยังไม่มีรูปห้องจริง), sidebar "สาขาอื่น" (อีก 2 สาขาจาก branches list เดียวกัน ไม่รวมตัวเอง — เรียก `GET /branches` เพิ่ม), การ์ด "รายละเอียด" (รายวัน/รายเดือน ใช้กฎ "-" เมื่อ key หาย, เงินประกัน ใช้กฎใน Gap, ค่าน้ำ, ค่าไฟ, ที่จอดรถ ใช้กฎใน Gap, จำนวนตึก, Line, เบอร์โทร, ที่อยู่), การ์ด "สิ่งอำนวยความสะดวก" (render จาก `branch.amenities` จริงด้วยไอคอนจาก FE-08 เท่านั้น)

**FE-11 · "สถานที่ใกล้เคียง" (จัดกลุ่มตามหมวด)**
- ทำ: จัดกลุ่ม `branch.nearby_places` ตาม `category` → หัวข้อภาษาไทย (`education`→"สถานศึกษา", `hospital`→"โรงพยาบาล", `shopping`→"ห้างสรรพสินค้าและแหล่งช้อปปิ้ง", `park`→"สวนสาธารณะ", category อื่นที่ไม่รู้จัก→ใช้ค่า category ดิบแทน fallback) เรียงภายในกลุ่มตาม `sort_order` แสดงคู่ชื่อ+ระยะทาง
- ขึ้นกับ: FE-10 (ใช้ response เดียวกัน ไม่ยิง API เพิ่ม)
- DoD: E2E checklist ครบ — **empty ต้อง cover เคสจริงที่ 2 ใน 3 สาขาไม่มี `nearby_places` เลย (key หายทั้ง key ไม่ใช่ array ว่าง) ต้องไม่ throw error และเห็นข้อความที่เหมาะสมแทนทั้ง section** · loading/error ผูกกับ call เดียวกับ FE-10 · success = ทดสอบกับสาขา "ประชาอุทิศ 45" (มีข้อมูลจริง 4 รายการ ครบ 3 หมวด) จัดกลุ่ม/เรียงลำดับตรงกับ `sort_order` จริง

- ขึ้นกับ: FE-10
- DoD: E2E checklist ครบ — loading/error/success ผูกกับ call เดียวกับ FE-10, empty = `map_url` ว่าง (เคสจริงตอนนี้ทั้ง 3 สาขา) ต้องเห็นข้อความ "ยังไม่มีแผนที่สำหรับสาขานี้" ไม่ใช่ error หรือ iframe ว่างเปล่า · deep-link เข้า `/branches/:id/map` ตรงจาก URL แล้ว tab แผนที่ต้อง active ทันทีโดยไม่ต้องกด
